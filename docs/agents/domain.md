# 领域文档

## 探索代码前

读取根目录 GLOSSARY.md，以及 docs/adr/ 中与当前任务相关的架构决策。

若根目录存在 GLOSSARY-MAP.md，则按其中映射读取相关上下文的术语表，
并检查对应上下文的架构决策。

这些文件不存在时直接继续，不提示缺失，也不提前建议创建。
由 domain-modeling 在术语或决策明确后按需生成。

## 当前布局

采用单上下文布局：

- GLOSSARY.md：统一领域术语。
- docs/adr/：架构决策记录。

## 术语使用

Issue 标题、重构建议、假设与测试名称中的领域概念，
应使用术语表定义的名称，避免使用其明确排除的同义词。

所需概念尚未收录时，先判断是否属于项目已有语言；
确有缺口时，记录供 domain-modeling 后续处理。

## 决策冲突

建议与已有 ADR 冲突时，明确指出对应 ADR、
冲突内容与重新讨论的理由，不默默覆盖已有决策。
