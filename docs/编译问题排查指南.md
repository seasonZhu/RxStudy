# Tuist 与 Xcode 排错指南

返回 [新手手册](工程生成新手实操手册.md)。先记录当前目录、分支、第一条实际错误及失败步骤，再按下面对应项处理。终端中查看当前状态：

```sh
pwd
git branch --show-current
xcodebuild -version
mise exec -- tuist version
```

最后一条只在 Tuist 工作目录执行。先确认打开的是这个目录的 workspace。

## 1. 工具找不到

**现象**：`mise: command not found`、`tuist: command not found`，或 SwiftGen 提示未安装。

**检查**：终端执行 `command -v mise`、`command -v swiftgen`。Homebrew 常见路径为 `/opt/homebrew/bin` 和 `/usr/local/bin`。终端找到工具而 Xcode 找不到时，检查构建脚本 PATH。

**修复**：缺失时安装对应工具。在 Tuist 目录运行 `mise install`，然后显式用 `mise exec -- tuist …`。项目 SwiftGen 脚本已补充两个 Homebrew 搜索路径；不要在生成目录中手写替代代码。

**验证**：`mise exec -- tuist version` 显示 4.200.4；`bash scripts/swiftgen.sh` 成功。

## 2. 依赖下载失败

**现象**：`tuist install` 报超时、Git clone 失败、无法连接仓库。

**检查**：先看失败的仓库地址与网络错误；确认网络、实际使用的代理和磁盘空间。它与 Swift 编译错误不同。

**修复**：恢复网络后重新安装依赖。代理只使用自己的有效配置，不复制文档里的假端口。不要为了绕过下载修改 lock、换未知依赖版本或删除全局缓存。也不要向当前仓库执行 `git fetch ... +refs/*:refs/*` 导入依赖仓库引用。

**验证**：安装成功后生成工程，再编译；lock 变更应符合依赖清单。

## 3. 找不到模块

**现象**：`No such module` 或 `Unable to find module dependency`。

**检查**：核对包的产品名、Swift import 模块名，以及使用它的 Target 是否声明了依赖。确认先完成安装依赖和生成工程。

**修复**：SPM 产品用 `.external`；项目内本地 Target 用 `.target`。不要只把一个包加入 Package.swift 就认为所有 Target 都能导入它。Objective-C 本地依赖还需要有效模块映射或桥接设置。

**验证**：生成工程后检查依赖图和对应 Target 的编译结果。

## 4. 新文件找不到或加入错误 Target

**现象**：新类型无法使用；UIKit 或 SwiftUI Target 编译了另一端的页面。

**检查**：真实路径是否匹配该 Target 的 sources glob；Xcode 的 Compile Sources 是否包含它。

**修复**：文件放入正确应用目录或 Shared 的相应子目录。在 Tuist 中改持久配置并重新生成，在 CocoaPods 工程中添加引用并设置 Target Membership。

**验证**：Xcode 显示正确层级，应用专属源码只加入一个 Target，共用源码加入两个。

## 5. 图片、字符串或资源异常

**现象**：`Asset`、`L10n` 找不到，图片缺失，Bundle 查找返回 nil。

**检查**：区分编译期生成代码与运行时资源。检查 `Shared/Generated`、`swiftgen.yml` 输入路径及 Target 的 resources 配置。图片名大小写需与实际名称一致。

**修复**：运行 SwiftGen；首次生成的源码必须在 `tuist generate` 前存在。新资源目录需要加入正确 Target 的 resources。不要恢复 R.swift 或重复加入旧的资源目录。

**验证**：编译通过，Copy Bundle Resources 和构建产物中有资源；读取与显示问题仍需运行应用确认。

## 6. 签名失败

**现象**：缺少 provisioning profile 或 Development Team。

**检查**：确认当前目标是真机还是仅做编译检查，所选 scheme 和 bundle ID 是否正确。

**修复**：真机使用自己的 Team，Tuist 将持久设置写回 Project.swift。只验证编译时，可用手册中的通用 iOS、`CODE_SIGNING_ALLOWED=NO` 命令。

**验证**：无签名编译显示 BUILD SUCCEEDED；实际安装仍需有效签名，不能用关闭签名代替。

## 7. 重复符号或重复资源

**现象**：链接报 `duplicate symbol`，或 `Multiple commands produce`。

**检查**：是否同时从 SPM 和本地源码集成同一库，或同一资源在阶段中出现多次。当前 UniMP 内置部分解压实现，ZipArchive 使用动态 framework。

**修复**：移除本次误加的重复来源或重复引用，保留项目已验证的依赖链接方式；不要修改业务代码掩盖链接错误。

**验证**：重新生成并编译受影响的 scheme。

## 最后才处理缓存

若配置和文件路径均正确，而日志表明存在陈旧工程信息，先重新生成工程。仍有具体证据时，再使用 Xcode 的 Product → Clean Build Folder 清理当前构建产物。

依赖下载异常先处理网络，签名异常先处理签名。删除全局 SPM 缓存、所有 DerivedData 或本机模拟器不属于本指南的常规修复步骤。
