# Tuist 配置示例

返回 [新手手册](../工程生成新手实操手册.md)。以下均为**局部片段**，按注明位置追加或核对，不覆盖整个配置文件。只在 Tuist 工作目录修改；CocoaPods 侧有自己的 Podfile 和工程引用。

## 1. SPM 包声明与 Target 引用

适用：库本身支持 SPM。以项目已经使用的 Kingfisher 演示，现有条目不要重复添加。

`Tuist/Package.swift` 的 `Package(dependencies: [...])` 中：

```swift
.package(url: "https://github.com/onevcat/Kingfisher.git", from: "8.6.3"),
```

`Project.swift` 中实际需要图片加载的 Target 的 `dependencies` 数组：

```swift
.external(name: "Kingfisher"),
```

然后在该 Target 的源码中使用 `import Kingfisher`。当前两个应用都已声明 Kingfisher。换成其他库时，先查看其 Package.swift 中的 products 和 targets，确认产品名与模块名，不照搬仓库名称。

验证：`mise exec -- tuist install` → `mise exec -- tuist generate` → 编译使用该库的 scheme。检查 lock 文件变化是否符合本次改动。

## 2. 按 Target 放置新页面

适用：新增 UIKit 或 SwiftUI 页面，不创建第三个应用。

- UIKit 文件放入 `RxStudy/Home/Controller` 等现有业务目录；现有 `RxStudy/**` glob 会在生成时收录。
- SwiftUI 文件放入 `SwiftUIStudy/Features/Home` 等目录；现有 `SwiftUIStudy/**/*.swift` 会在生成时收录。

这两条规则已经存在，不需要重复追加。重新生成工程后，在 Xcode 检查文件只属于对应 Target，再编译对应 scheme。

不要把 `SwiftUIStudy/**` 加入 RxStudy sources，也不要把 `RxStudy/**` 加入 SwiftUIStudy sources。生成的工程里手动勾选 Target Membership 不会成为持久配置，应修改 `Project.swift`。

## 3. 新增共享模型或规则

适用：代码可被两种 UI 共用，不依赖某一端页面或专有模块。

文件放入 `Shared/Models` 或 `Shared/Business` 时，两个 Target 已有对应 glob，重新生成即可。CocoaPods 工程中只添加一次文件引用，并勾选两个 Target。

若确实需要新增 `Shared/Utilities` 子目录，先创建实际 Swift 文件，再在两个 Target 的 `sources` 数组各追加一次：

```swift
"Shared/Utilities/**/*.swift",
```

不要只创建空目录并期待 Xcode 显示它，也不要将同一源码复制成两份。

验证：重新生成后，文件在 Shared 分组中出现一次、两个应用都编译它；编译两个 scheme，并运行源码比较脚本。

## 4. 给两个 Target 加入共享资源

适用：例如两端都需要读取一份新增 JSON 配置。

先创建 `Shared/Resources/Config` 中的实际资源文件，再在两个 Target 的 `resources` 数组各加入：

```swift
"Shared/Resources/Config/**",
```

若仅 UIKit 使用，只加到 RxStudy；若仅 SwiftUI 使用，将文件放入 SwiftUIStudy 的专用资源目录，并只声明在 SwiftUIStudy 中。新增资源目录不会因为存在于 sources 中就自动变成运行时资源。

JSON 读取按文件名和后缀查找，例如文件实际名为 `FeatureConfig.json` 时：

```swift
let url = Bundle.main.url(forResource: "FeatureConfig", withExtension: "json")
```

CocoaPods 侧添加同一文件引用并确认资源 Target Membership。验证：生成后检查对应 Target 的 Copy Bundle Resources，编译并检查构建产物中的资源；需要验证读取行为时再运行应用。

当前共享图片已由 `Shared/Resources/Assets.xcassets/**` 收录，不再重复添加第二个 asset catalog。新增图片后执行 SwiftGen。

## 5. 在工程导航展示头文件与配置

适用：文件已在磁盘上，但导航栏看不到。

`Project.swift` 的 `additionalFiles` 已包含：

```swift
"RxStudy/**/*.h",
"RxStudy/Info.plist",
"SwiftUIStudy/Info.plist",
"scripts/**",
```

现有路径不要重复加。新配置目录可用同样的 glob 规则追加。重新生成后检查导航树。

`additionalFiles` 只控制展示，不把文件加入编译或打包，也不修复桥接错误。当前 UIKit Target 的桥接设置为：

```swift
"SWIFT_OBJC_BRIDGING_HEADER": "$(SRCROOT)/RxStudy/RxStudy-Bridging-Header.h",
```

若新增 Objective-C 接口，复用现有桥接头并检查所在目录的 HEADER_SEARCH_PATHS。只修改实际需要它的 Target，不把 UIKit 桥接头复制给 SwiftUI Target。

## 6. 识别本地依赖引用

适用：维护已有旧实验，不把示例当作新增依赖的默认路线。

FlexLayout 的本地 Target 由 `Tuist/ProjectDescriptionHelpers/LocalDependencies.swift` 定义。应用 Target 使用：

```swift
.target(name: "FlexLayout"),
```

这与 `.external(name: "Kingfisher")` 不同。FSPagerView 则是本地 SPM 包，Package.swift 中的相对路径为：

```swift
.package(path: "../Packages/ThirdParty/FSPagerView"),
```

该路径相对 `Tuist/Package.swift` 所在目录，而不是相对当前终端工作目录。

UniMP 使用已有二进制、头文件、资源和链接设置，保持完整配置。不要只拷贝一条库路径，也不要将已有静态库改为动态库。任何新增二进制依赖都需单独确认支持的平台、架构和链接方式。

## 每次配置变化后的检查

1. 检查真实文件是否位于声明路径下。
2. 依赖发生变化时先安装依赖，再生成工程。
3. 检查工程导航和正确的 Target 编译或资源阶段。
4. 编译受影响的 scheme；共享变更检查两个 scheme。
5. 提交源码、配置和必要的 lock 变化，不提交 Tuist 生成工程。
