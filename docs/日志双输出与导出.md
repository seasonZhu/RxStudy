# RxStudy 新旧日志体系切换

## 唯一开关

在 `RxStudy/Log/Modern/LoggingConfiguration.swift` 修改一处，重新编译并启动：

```swift
enum LoggingConfiguration {
    static let mode: LoggingMode = .legacy
}
```

- `.legacy`：默认值，沿用旧日志体系。
- `.modern`：启用独立的新日志体系。

每次启动只启用一套，不支持运行中切换，不添加设置页面。两种模式均编译进 UIKit RxStudy，SwiftUIStudy 不引用新模块。切回 `.legacy` 后重新编译启动即可回退，不需要删除新日志文件。

## 保留旧实现的边界

旧 `NetworkActivityLogger`、`CustomLogFileManager`、`LogUtils` 与本次改造前逐字节一致。旧文件只增加三个接入点：AppDelegate 在新模式下提前启动新模块；旧网络初始化、旧日志初始化各增加一个模式判断。旧模式初始化顺序、print 网络日志、文件目录及 uploadLogs() 均沿用原实现，原有局限也保留。

新代码集中于 `RxStudy/Log/Modern/`，不依赖旧自定义日志类。没有改动业务日志调用、网络请求、Moya 插件集合或依赖版本。

| 行为 | 旧体系 | 新体系 |
|---|---|---|
| 系统接收器 | 原 DDOSLogger.sharedInstance | 独立配置 subsystem/category 的 DDOSLogger |
| 业务 DDLog 调用 | 进入旧接收器 | 进入新接收器 |
| 网络日志 | 原实现的 Debug print | Debug 系统摘要＋文件详情；Release 仅失败摘要 |
| App 日志目录 | Documents/Logs | Documents/ModernLogs |
| 日志清理 | 原实现 | 框架负责数量与配额清理 |
| 导出入口 | 原 uploadLogs()，行为不变 | ModernLogging.shared.exportLogs(completion:) |

新旧目录是同级目录，不会被对方枚举。新体系不读取、清理或导出旧目录，也不识别旧版下划线日期文件名。新模块自身使用当前 Bundle ID 和 category `app`；原生全局 logger 仍使用原来的 `season/debug`，未为统一 subsystem 修改旧代码。

## 新体系的行为

- Alamofire 请求按自身 UUID 关联；监听请求与 task 恢复事件并去重，以补齐 URLRequest 尚未创建的时序。失败包括传输、创建、校验失败及 HTTP 4xx/5xx。缺少 task 或 metrics 时仍记录失败。
- Debug 系统日志只记录摘要，文件保留脱敏请求头、请求体及响应体。Release 仅记录失败摘要，不记录成功请求和网络正文。
- URL 移除认证信息和 fragment、隐藏敏感查询值；请求头只放行内容类型、长度、Accept 和 Accept-Encoding，其他值隐藏。JSON 递归脱敏，表单按字段脱敏；手机号、邮箱及 Bearer 凭据另做字符串替换。规则随业务敏感字段维护。
- 正文最大记录 64 KiB；超限原文整体省略并标注大小，脱敏后膨胀的文本再限长。二进制只记录类型、大小，无法结构化脱敏的文本不输出原文。
- 每日或达到 1 MiB 后轮转，最多 7 个归档、10 MiB 配额，活动文件受保护。1 MiB 是写完条目后的轮转触发值，不是单文件绝对上限。

新导出接口：

```swift
ModernLogging.shared.exportLogs { result in
    switch result {
    case .success(let url):
        // 调用方使用 url 分享文件，并在使用完成后清理本次 ZIP。
        break
    case .failure(let error):
        // 调用方展示 error.localizedDescription。
        break
    }
}
```

回调在主队列。后台等待刷盘、轮转，再复制快照并压缩。临时快照始终清理；成功 ZIP 留在临时目录 `ModernLogExports`，返回前不删除。不新增上传服务或导出页面。

旧模式调用新接口返回“新日志体系未启用”，不会隐式启动或切换。新模式尚未初始化、无日志、文件操作失败及压缩失败均返回错误。原 AppDelegate.uploadLogs() 未改成新接口，使用新体系时应显式调用上述新接口。

## 电脑端查看

新模式使用系统日志监听，在手机操作前开启：

```bash
"/Users/dy/Desktop/iOSLog/ioslog.command" --mode listen --filter all --bundle '<实际安装包 Bundle ID>'
```

同时用 Mac“控制台”选择设备、启用 Info/Debug 消息，按 RxStudy 进程或实际 Bundle ID 搜索，以请求 ID 交叉核对。完整正文通过新接口导出复盘。

默认旧模式的网络日志仍是 print，查看这部分通常需要 iOSLog 的 `--mode launch --filter all`，该模式会重启 App。切换日志体系不会修改电脑端工具。
