## 认识两个构建方式

本项目已完成 Tuist 工程配置。切换到 Tuist 时不需要再迁移一次，打开对应工作目录即可。

| 项目 | CocoaPods 工作目录 | Tuist 工作目录 |
| --- | --- | --- |
| 当前分支 | `codex/pods-dual-target` | `develop-tuist` |
| 依赖声明 | `Podfile` | `Tuist/Package.swift`、本地依赖配置 |
| 固定解析结果 | `Podfile.lock` | `Tuist/Package.resolved` |
| 安装依赖 | `pod install` | `mise exec -- tuist install` |
| 工程定义 | 手工维护 `.xcodeproj` | `Project.swift` |
| 生成工程 | CocoaPods 安装时集成 Pods | `mise exec -- tuist generate` |
| 打开入口 | `RxStudy.xcworkspace` | `RxStudy.xcworkspace` |

**Tuist 是工程生成工具。** 当前 Tuist 分支主要通过 SPM 获取第三方库，再生成 Xcode 工程；旧实验中的部分依赖使用本地源码或二进制。切换构建方式不会把 RxSwift 页面改成 SwiftUI 页面，两个分支都包含两个应用 Target。

两个 workspace 名字相同，但所在目录不同。推荐保持独立 worktree，避免生成工程和依赖缓存相互覆盖。`develop` 仍保留原来的提交；双 Target 的 CocoaPods 改造在独立分支上。

## 准备工具

### 1. 确认 Xcode

```sh
xcode-select -p
xcodebuild -version
```

第一条应指向完整 Xcode 的 Developer 目录；第二条应显示 Xcode 版本。若只指向 CommandLineTools，先在 Xcode 的 Settings → Locations 中选择正确的 Command Line Tools。

此前已完成两个构建方式、四个 scheme 的无签名通用 iOS 编译验证。本次文档核对时本机为 Xcode 26.3；本次文档调整不重新验证编译、模拟器或真机功能。

### 2. 安装 mise 和 SwiftGen

已有 Homebrew 时执行：

```sh
brew install mise swiftgen
mise --version
swiftgen --version
```

没有 Homebrew 时先按 [Homebrew 官方说明](https://brew.sh/)安装。mise 管理 Tuist 版本；SwiftGen 生成图片和本地化字符串的 Swift 访问代码。项目已经移除 R.swift，资源入口使用 `Asset` 与 `L10n`。

### 3. 在 Tuist 目录安装固定版本

```sh
cd "/Users/dy/.codex/worktrees/rxstudy-tuist/RxStudy"
mise install
mise exec -- tuist version
```

最后一条应输出 `4.200.4`。版本来自仓库的 `mise.toml`，不要为了打开项目改成 `latest`。如果 mise 提示配置未被信任，先查看当前目录的 `mise.toml`，确认来自本项目，再运行 `mise trust` 后重试。

`mise exec --` 显式使用项目工具版本，因此不要求先配置 shell 激活，也能避免调用另一份全局 Tuist。首次安装需要下载工具。

## 首次打开 Tuist 工程

### 已有本项目的两个工作目录

本机当前目录如下；别人的电脑使用自己的实际路径。

| 构建方式 | 工作目录 |
| --- | --- |
| CocoaPods | `/Users/dy/Documents/Swift Git/RxStudy` |
| Tuist | `/Users/dy/.codex/worktrees/rxstudy-tuist/RxStudy` |

在终端依次运行，每一步成功后再继续：

```sh
cd "/Users/dy/.codex/worktrees/rxstudy-tuist/RxStudy"
git branch --show-current
mise install
bash scripts/swiftgen.sh
mise exec -- tuist install
mise exec -- tuist generate --no-open
open RxStudy.xcworkspace
```

| 步骤 | 成功后的结果 |
| --- | --- |
| 查看分支 | 显示 `develop-tuist` |
| `mise install` | 固定版本工具安装完成 |
| SwiftGen | `Shared/Generated` 中有 Assets 和 Strings 两个 Swift 文件 |
| `tuist install` | 依赖解析和下载完成；首次运行可能较慢 |
| `tuist generate` | 显示工程生成成功，出现 `.xcworkspace` 与 `.xcodeproj` |
| `open` | Xcode 打开 Tuist 工作目录中的 workspace |

SwiftGen 放在生成工程之前：Tuist 需要在生成阶段发现这些源码文件。不要用 `tuist init` 初始化已有项目，也不要在这个目录执行 `pod install`。

### 新克隆仓库时创建独立 worktree

进入自己的 RxStudy 仓库，先只读检查：

```sh
git status --short
git remote -v
git branch -a
git worktree list
```

先保存需要保留的未提交工作。若列表中已有 `develop-tuist` 的工作目录，直接使用它，不重复创建。若本地已有该分支且尚未被 worktree 使用：

```sh
git worktree add ../RxStudy-Tuist develop-tuist
cd ../RxStudy-Tuist
```

若只有远端分支，执行下面的替代命令。`<远端名>` 根据 `git remote -v` 替换；本仓库原工作环境为 `remote`，新克隆通常是 `origin`：

```sh
# 替换占位符后运行；与上面的本地分支命令二选一。
git worktree add -b develop-tuist ../RxStudy-Tuist <远端名>/develop-tuist
```

如果本地和远端都没有该分支，先取得包含 Tuist 改造的分支，不从任意提交创建空的 `develop-tuist`。本次改造分支可能尚未推送，不能假定新克隆一定能找到它。

进入新 worktree 后，执行本节的 SwiftGen、安装依赖、生成工程和打开 workspace 步骤。

### 回到 CocoaPods

关闭或切换当前 Xcode 窗口，打开另一个目录：

```sh
cd "/Users/dy/Documents/Swift Git/RxStudy"
open RxStudy.xcworkspace
```

首次准备 CocoaPods 目录或修改 Podfile 后，先运行 `bash scripts/swiftgen.sh` 与 `pod install`。两个目录可以同时保留；切换工作不需要在同一个目录来回 checkout 分支。

## 选择 Target 并编译

Xcode 顶部选择 scheme：

- `RxStudy`：UIKit + RxSwift，包含原有实验功能。
- `SwiftUIStudy`：独立 SwiftUI 应用。

按 ⌘B 编译。只检查编译时可以选择通用 iOS 构建目标，不要求启动模拟器。要运行真机，在对应 Target 的 Signing & Capabilities 中设置自己的 Team；Tuist 工程中的设置需要同步写回 `Project.swift`，否则重新生成会覆盖手工修改。

终端无签名编译示例，在对应工作目录执行：

```sh
xcodebuild -workspace RxStudy.xcworkspace -scheme RxStudy -configuration Debug -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -workspace RxStudy.xcworkspace -scheme SwiftUIStudy -configuration Debug -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

成功标志为 `BUILD SUCCEEDED`。关闭签名只用于编译检查，不产生可直接安装到真机的签名应用。

## 日常开发该运行什么

| 操作 | Tuist 目录中的步骤 |
| --- | --- |
| 修改已加入工程的 Swift 文件 | 直接编译 |
| 新增、删除、移动源码文件 | 检查 sources 路径，再 `mise exec -- tuist generate` |
| 修改图片或字符串 | `bash scripts/swiftgen.sh`，再编译；新增资源路径时还需重新生成工程 |
| 修改 Info.plist 内容 | 直接编译；更换文件路径时重新生成工程 |
| 修改 Target、scheme、编译设置、资源归属 | 修改 `Project.swift`，再生成工程 |
| 添加或修改 SPM 依赖 | 修改依赖清单和 Target 引用，再安装依赖、生成工程、编译 |
| 拉取包含依赖或工程配置变更的提交 | SwiftGen → 安装依赖 → 生成工程 → 编译 |

已有资源生成文件时不必每次重新安装依赖。Tuist 的 glob 在**生成工程时**扫描目录；新增文件放进目录后，旧工程不会自动认识它。

CocoaPods 工程由 Xcode 手工维护，新增文件还要确认工程引用和 Target Membership；不能套用 Tuist 的自动扫描规则。

## 添加依赖和文件

### 两步加入 SPM 依赖

1. 在 `Tuist/Package.swift` 的 `dependencies` 中声明包地址和版本。
2. 在 `Project.swift` 中所需 Target 的 `dependencies` 中声明 `.external(name: "产品名")`。

包名、仓库名、产品名和 Swift 的 `import` 模块名可能不同。只声明包而不添加 Target 引用，不能保证页面能导入模块。

修改后执行：

```sh
mise exec -- tuist install
mise exec -- tuist generate
```

再编译实际使用该依赖的 scheme，检查并提交依赖声明及 `Tuist/Package.resolved` 的合理变更。`from:` 是版本范围，lock 文件记录本次解析结果；不要手动编辑 lock 文件来升级依赖。

### 文件应放在哪里

```text
RxStudy/                 UIKit 入口、基础类、业务模块与实验
SwiftUIStudy/            SwiftUI 入口、Features、Components、Network 等
Shared/                  两端确实共用的 API、模型、规则、组件和资源
Packages/ThirdParty/     第三方源码及旧实验二进制
scripts/                 构建辅助脚本
```

UIKit 页面放到已有的 `RxStudy/Home`、`Account` 等模块；SwiftUI 页面放到 `SwiftUIStudy/Features` 下。共用模型进入 `Shared/Models`；共用规则进入 `Shared/Business`。不要为了复用目录而让共享代码依赖某个应用的账户管理器或页面。

工程中的共用文件只保留一份引用，但可以加入两个 Target 的编译阶段。目前两个 Target 各编译 14 个 Shared 源文件。资源归属单独设置：图片和启动页共享；UIKit 主界面、JavaScript、UniMP 包只供 UIKit 使用。

Tuist 生成工程中的 `Project` 分组是目录容器。头文件出现在导航中与头文件能被编译器找到是两件事：`additionalFiles` 控制展示，桥接和头文件搜索路径控制编译。

具体可复制片段见 [配置示例](配置示例/工程配置示例.md)。

### 本地依赖的例外

旧实验中的 FlexLayout、CocoaDebug 等由 `Tuist/ProjectDescriptionHelpers/LocalDependencies.swift` 定义本地 Target；TheRouter 直接加入应用源码；UniMP 保留本地二进制、头文件和资源。它们不是普通远端包，不能一律用 `.external` 替换。

例如 ZipArchive 当前使用动态 framework，避免和 UniMP 内置解压代码重复链接。新增库时先检查是否重复引入已有能力，不要随意统一所有依赖的链接类型。

## 共享代码与分支同步

两个分支分别维护构建配置，应用源码应保持一致。两条历史没有共同祖先，日常同步以小范围文件或补丁为单位，不整分支合并。

1. 在当前分支完成修改，并列出涉及的文件。
2. 区分应用源码与构建配置。源码和业务资源同步；Podfile、Tuist 配置、生成工程不跨目录覆盖。
3. 将需要同步的文件复制到另一 worktree 的相同相对路径；先检查目标是否有未提交修改，保留其工作。
4. CocoaPods 新文件补充工程引用；Tuist 新文件重新生成工程。
5. 比较应用源码，再编译受影响的 Target。两端共用代码变化时检查两端。

本机检查示例：

```sh
python3 scripts/check-shared-sources.py "/Users/dy/Documents/Swift Git/RxStudy" "/Users/dy/.codex/worktrees/rxstudy-tuist/RxStudy"
```

期望输出 `不同文件: 0`，退出码为 0。这个脚本比较应用源码目录，排除生成代码等文件；它不验证业务行为，也不要求依赖管理配置一致。

Tuist 分支提交源码、配置、版本锁和需要的本地依赖；生成的 `.xcodeproj`、`.xcworkspace`、依赖缓存及 `Shared/Generated` 不提交。CocoaPods 分支继续维护现有工程文件和锁文件，遵循其既有 Pods 跟踪约定。

## 遇到问题

先找到日志中第一条实际错误，记录当前目录、分支、失败步骤和工具版本。按 [排错指南](编译问题排查指南.md) 分别检查工具、依赖、模块、文件归属、资源与签名。不要把每次失败都处理成重装或删除所有缓存。
