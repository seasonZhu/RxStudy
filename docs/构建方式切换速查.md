# CocoaPods 与 Tuist 切换速查

统一使用 `/Users/dy/Documents/Swift Git/RxStudy`。本地分支为 `develop-pods` 与 `develop-tuist`，业务源码的相对路径和双 Target 结构保持一致。

## 一键切换

先关闭当前 Xcode 工程并保存 Git 修改，再运行：

```sh
cd "/Users/dy/Documents/Swift Git/RxStudy"
bash scripts/switch-dependencies.sh
# 或直接指定方案：
bash scripts/switch-dependencies.sh pods
bash scripts/switch-dependencies.sh tuist
```

CocoaPods：切换 `develop-pods` → SwiftGen → `pod install --deployment` → 打开 workspace。
Tuist：切换 `develop-tuist` → `mise install` → SwiftGen → `tuist install --force-resolved-versions --skip-update` → `tuist generate --no-open` → 打开 workspace。

预先安装完整 Xcode、CocoaPods、mise、SwiftGen。Tuist 精确版本以 `develop-tuist` 的 `mise.toml` 为准；首次使用先检查 `mise.toml`，若提示不可信，确认配置后执行 `mise trust`。安装强制使用现有锁文件，跳过不必要的远端更新查询；缺失依赖仍需下载，不主动升级依赖。修改依赖声明后，应在对应分支手动更新锁文件并提交，再使用切换脚本。

## 独立检查与升级 Tuist

```sh
# 任一分支只检查：项目版本、官方仓库最新稳定版本、本机安装列表
bash scripts/upgrade-tuist.sh --check

# 升级必须在 develop-tuist，先保存所有修改
bash scripts/switch-dependencies.sh tuist
bash scripts/upgrade-tuist.sh
```

需要 Python 3、mise、Git、SwiftGen 和完整 Xcode。脚本从 Tuist 官方仓库标签过滤三段数字稳定版本，排除 app、其他产品、RC 与 Canary，避开旧插件 latest 误识别和 GitHub API 限流；不自动升级 mise 或插件。

升级顺序为：安装明确的新版本 → 核验 CLI → SwiftGen → 新版安装锁定依赖 → 新版生成工程 → 更新 `mise.toml` → 清理更早版本 → 打开工程。第三方库版本保持锁定，日常切换仍使用项目精确版本。

成功后请检查并提交 `mise.toml`。脚本不自动提交；有未保存修改时禁止再次升级或切换。若新版不兼容、网络失败或意外修改锁文件，保留旧项目版本和旧安装，不清理、不自动迁移源码，打印恢复命令。先检查保存意外修改，再按提示用旧版重新安装、生成。

上一版本记录保存在仓库 Git 公共目录的 `tuist-upgrade-state.json`，不提交、不跨电脑同步。重复运行会保留此记录；首次运行已经是最新版且没有记录时，将本机已安装的最高较低稳定版作为回退版。手动恢复版本时，在 `mise.toml` 将 Tuist 改回记录的上一版，再运行 `mise install`、SwiftGen、`tuist install --force-resolved-versions --skip-update` 和 `tuist generate --no-open`（Tuist 命令加 `mise exec --`）。

清理仅限 mise 标记可清理且早于保留版本的普通 Tuist 安装。保留当前版和上一版，跳过其他已登记项目引用、外部符号链接及 Homebrew 安装，列出候选后逐个卸载，不直接删除目录。未登记的项目引用无法自动识别；需要保留的工具版本应先在 mise 项目配置中登记。清理失败返回非零状态，但已经成功的项目升级保留。

## 安全与重试

- 未提交或未跟踪修改、进行中的 Git 操作、分支被其他 worktree 占用时立即停止；不自动 stash。
- 一个仓库同时只运行一个切换任务。异常终止遗留锁时，先确认没有任务运行，再移除错误信息指向的锁目录。
- 切回 CocoaPods 前，脚本只备份并移除未跟踪且被忽略的 Tuist 根工程和 FSPagerView 嵌套工程目录，备份路径会打印在终端。不会执行全局清理。备份位于系统临时目录，长期需要的工程设置请自行转存。
- 其他被忽略文件发生检出碰撞时停止，不覆盖。依据 Git 提示人工检查并备份冲突文件后重试。
- 安装或生成失败不会自动回滚分支；修复错误后原命令可重试。若产生 Git 修改，先检查并保存。
- 两个分支都需包含同一份脚本。重复选择当前方案会重新安装和生成。

`cocoapods-keys` 每次安装随机生成的 `RxStudyKeys.h/.m` 由插件维护，CocoaPods 分支不再跟踪这两个生成文件，避免正常安装产生无意义的 Git 修改。

## 业务代码同步

脚本只准备工程，不同步业务提交。在主要开发分支完成纯业务提交后，切换另一分支并执行 `git cherry-pick <提交号>`。两条历史没有共同祖先，不整分支合并；遇到冲突先检查再解决。

业务代码与依赖／工程配置分开提交。CocoaPods 新文件需补工程引用与 Target Membership；Tuist 新文件需重新生成。提交同步完成后，再运行对应切换命令准备工程。
